# PLAN.md — Phased build for opencode

Repo layout to create (see SPEC.md §7 for detail):
`src/sentinel/{config,ingest,metrics,detect,output}.py`, `src/sentinel/notes/{extract,index,retrieve}.py`, `src/sentinel/agent/{state,tools,gate,explain,verify,graph}.py`, `src/sentinel/llm/{client,ledger}.py`, `src/sentinel/qa/`, `eval/`, `tests/`, `data/` (copy the 3 provided CSVs), `fixtures/` (provided, read-only).

Fixtures provided in `fixtures/`:
- `expected_candidates.csv` — the 13 rows the default rule must produce, with expected verdict/note. Rows tagged `debatable` are the strict-window judgement calls.
- `reference_weekly_metrics.csv` — 728 route-weeks with cpt, n_prior, own_pct, peer_pct (generated by a separate script; use for numeric cross-checks, tolerance 1e-6).
- `golden_notes.json` — hand-labelled extraction for the 10 notes.
- `sample_output_format_v2.csv` — format contract.

---

## Phase 0 — Skeleton
Tasks: repo structure, `pyproject`/`requirements.lock`, `config.yaml` (thresholds, seeds, model name, k, absorption_weeks=8, grace_days=0, min_history=4), Makefile, CLI stub `python -m sentinel run [--no-llm]`.
**Accept:** `make lint && make test` run (zero tests is OK).

## Phase 1 — Ingest + metrics (no AI)
Tasks: `ingest.py` (validate: positive qty/dist/cost, route_type ∈ Short/Medium/Long and unique per route, log row counts), `metrics.py` (week bucketing, pooled cpt, own-history, peers per AGENTS.md definitions).
Tests: week boundaries (Sunday vs Monday, 2024-12-30); pooled-ratio hand fixture; **no look-ahead** (perturb current week cost → `hist` unchanged); `<8` prior weeks; first week NaN; peer excludes self; single-peer groups; row-shuffle invariance (hypothesis).
**Accept:** `pytest tests/test_metrics.py` green AND all 728 rows match `fixtures/reference_weekly_metrics.csv` within 1e-6 (`tests/test_reference.py`). Also add an independent DuckDB-SQL implementation test that agrees with the pandas one.

## Phase 2 — Detector + output writer (`--no-llm`)
Tasks: `detect.py` (candidate rule), `output.py` (contract formatting, sort), template reasons: justified/unexplained styles from SPEC §6.4. At this phase every candidate may be `Yes` (gate not built yet); that is fine.
**Accept:** candidates `(route, week_of)` set equals `fixtures/expected_candidates.csv` exactly; contract tests green (header, order, regexes, blank-id rule, sample-format reproduction).

## Phase 3 — Notes: extraction + index + retrieval
Tasks: `notes/extract.py`: deterministic regex/rule extractor first (dates incl. year inference from note date, `5-7%`, polarity keywords: "not significantly affected", "no rate change", "absorbed", "not part of this dataset", "returned to normal", "improved", "no significant disruptions", "remained stable"). Output schema per SPEC §6.1. Then optional SLM extraction cross-checked against rules; on disagreement choose the conservative value and set `confidence=low`. `index.py`: bge-small embeddings + exact (flat) vector search + BM25, RRF fusion k=60, stable tie-break `(−score, note_id)`. `retrieve.py`: multi-query construction (SPEC §6.2), `--bruteforce` flag that scores all notes.
**Accept:** rule-based extraction matches `fixtures/golden_notes.json` 100% on scope, effect, start, end, open_ended, magnitude. `make eval` prints Recall@4 and MRR for dense/BM25/hybrid on the labelled rows; hybrid retrieval returns each gold note (N001, N002) in top-4 for its rows.

## Phase 4 — Evidence gate + agent graph
Tasks: `gate.py` (G1–G5, absorption window, tie-break, returns pass/fail with rule ids), `tools.py` (`search_notes`, `check_applicability`, `write_reason`, `verify_claims`), `graph.py` (plan → retrieve → gate → decide → explain → verify as a typed state machine; retrieval trace stored in `outputs/findings.sqlite`).
**Accept:** every row in `expected_candidates.csv` gets the expected `flagged` and `matched_note_id` in `--no-llm` mode. Rows tagged `debatable` must come out `Yes` under default config. Unit tests show each distractor is rejected for its specific rule: N004 (G3), N005 (G3), N006 (G3), N007 (G2+G3), N008 (G3), N009 (G3), N010 (G3), N001 vs week 2025-03-10 (G2), N003 vs Mumbai-Pune 2025-09 (G2 absorption).

## Phase 5 — LLM layer (skip with note in NOTES.md if Ollama unavailable)
Tasks: `llm/client.py` (Ollama, deterministic params, JSON-schema output, cache, ledger), `explain.py` (fact-sheet-only prompts), `verify.py` (claim verifier, one retry, template fallback), optional SLM note extraction.
**Accept:** verdict, `matched_note_id`, and all numeric columns identical between `--no-llm` and LLM runs; `fallback_rate` and token counts logged; a unit test where the model is stubbed to emit a fake note id `N011` and a made-up cause both fall back to the template.

## Phase 6 — Evaluation harness
Tasks: `eval/run_eval.py` printing one scorecard: unit-test status, silver-label precision/recall/verdict accuracy (report with and without debatable rows), retrieval metrics, red-team suite from `eval/adversarial_cases.yaml` (SPEC §9.5: delete N001, wrong route, shifted date, polarity flip, prompt-injection note, old generic fuel note, fabricated id, unsupported cause, empty notes), synthetic injection benchmark (`inject_anomalies.py`, fixed seed, recall vs magnitude, false positives per 100 route-weeks), threshold sweep table (own ∈ 4..15%, peer ∈ 5..25%).
**Accept:** red-team 100%; silver verdict accuracy 100%; scorecard saved to `outputs/eval_report.md`.

## Phase 7 — Reproducibility + cost
Tasks: `make repro` runs 3 fresh processes (run 2 with `--no-cache`, run 3 with `--no-llm`), diffs the 7 non-`reason` columns, writes hashes to `outputs/repro/repro_report.md`. `make cost` does a cold-cache full run and writes `outputs/token_cost_log.json` (calls, input/output tokens, cache hits, fallback rate, local cost 0, placeholder for hosted rate to be filled by the human).
**Accept:** non-`reason` diff empty across all 3 runs.

## Phase 8 — Q&A stretch
Tasks: `qa/` — question → structured query (model or rules), deterministic queries on `findings.sqlite`, answer composed only from results, verifier, refusal when no data, clarification when year is ambiguous.
**Accept:** scripted tests: "why did Chennai-Bangalore get pricier in March?" (asks which year or answers 2025 citing N001/N009 and the unexplained weeks), "why did Kolkata-Bhubaneswar get pricier?" (no flagged weeks → says so), "did N004 raise Mumbai-Pune costs?" (cites that N004 says affected routes are not in the dataset).

## Phase 9 — Docs and cleanup
Tasks: README per SPEC §12 (definitions, how AI is used and not used, gate table over N001–N010, eval scorecard, repro result, cost log, assumptions, limitations, the March-10/17 judgement call, v1/v2 file-name note, `<8 weeks` behaviour). `ruff`, `mypy` clean. Fresh-venv quickstart test.
**Accept:** `make lint && make test && make eval && make repro` all green from a clean clone.

- Candidate set differs from `expected_candidates.csv` after Phase 2.
- You want to change a threshold, add a dependency, or loosen a test.
- Ollama/model unavailable (record in NOTES.md, proceed with no-LLM path).
